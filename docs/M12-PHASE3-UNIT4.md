# M12 Phase 3 Unit 4 — offline runtime integration

## Actual entry points and ownership

`backtest.py` is the separate legacy benchmark and is unchanged. Before this unit,
`CandleDecisionDriver.observe()` was called by tests, not by the M8/M9.1 paper
actors. `trading/orchestration.py` is the M9.3 offline replay entry point for
submitted event frames; it does not ingest M12 candles or drive the M12 exit
controller. `DurablePaperExecution` journals only callbacks against a bridge
that already contains admissions. This unit adds `OfflinePaperRuntime.frame()`
as an explicit, offline session entry point. A caller supplies completed 5m
`CandleInput` values and actual receipt times; no transport or venue is present.

Call path: source candle → `CandleDecisionDriver.observe()` → M3/M5/M6 analysis
and M7 `SignalTracker` → M7 terminal handoffs through
`ExitFundingController.on_signal_terminal()` → explicit M8 portfolio quotes →
Phase 2 funding settlement and exit observation → `proposal_from_m7()` and
`RiskEngine.evaluate()` → `FreqtradeSimulationBridge.propose()` →
`OfflinePaperExecution.acknowledge()`. Explicit simulated entry/exit fills and
cancellations use the Unit 2 adapter; `ExitFundingController` creates automatic
stop/target exits through M9.1. M8 alone owns reservations, positions, cash and
funding accounting. Unit 1 reconciliation reads the resulting actors.

The fresh factory passed to `create()`/`recover()` returns a dictionary of
empty `CandleDecisionDriver` actors for BTC/USDT and ETH/USDT plus a fresh
`FreqtradeSimulationBridge` with its M8 risk/portfolio actor. The factory and
source inputs are caller supplied. Configuration and source identities, actor
code bytes, and BTC/ETH priority are pinned by journal baseline/code hashes.
The explicit asset priority determines capital allocation when both assets
have the same receipt timestamp; neither choice is unbiased.

## Durable command protocol

`RuntimeJournal` uses the accepted Unit 3 SQLite schema, hash chains,
PENDING/APPLIED/QUARANTINED outcomes, full synchronization and writer epochs.
Each authoritative top-level call gets its own PENDING row before invocation
and APPLIED outcome after its result. Commands are FRAME, TERMINAL, QUOTE,
FUNDING, EXIT_FRAME, RISK, ADMIT, ACK, EXPIRE, ENTRY_FILL, EXIT_FILL and CANCEL.
FRAME_DONE seals the completed frame handoff. M8 portfolio mutations nested
inside `bridge.propose()`, a fill or the Phase 2 controller are not replayed a
second time. The FRAME outcome records original M7 pattern, signal and terminal
IDs. FRAME_DONE records the ordered terminal receipts, funding observations,
exit lifecycle IDs, M8 decision IDs and M9.1 admission IDs.
The hot path hashes each command and current actor snapshot with a rolling
state identity. It reads actor history tails through pinned private fields
to avoid copying full histories on every 5m bar; a change to those internals
changes the pinned code hash and requires fresh validation. Full Unit 1
historical reconciliation runs after recovery and at an explicit `reconcile()`
checkpoint, rather than after every journal substep. The visible actor state is
checked before each new command; out-of-band actor mutation quarantines the
current runtime before it can append another event.

Before processing another source frame, every M7 terminal generated by the
current `CandleDecisionDriver.observe()` is committed through M9.1. This holds
for invalidations discovered during signal monitoring. Quote, funding, exit,
risk and admission work follow the terminal barrier. Funding observations in a
frame must be available at that exact frame receipt and must match its asset;
earlier or later observations require their own `funding()` command at the true
receipt time. No missing FX, fee model, instrument rule, funding rate or fill is
inferred. A qualified signal with missing risk inputs quarantines its RISK
command. M8 REJECTED/BLOCKED outcomes can produce only DENIED admissions.
Frame funding is checked before FRAME persistence for typed observation fields,
asset, exact receipt, completed-candle settlement, historical eligibility,
matching frame quotes when supplied, and duplicate IDs or settlement slots.
State-dependent funding checks remain with the Phase 2 controller.

An APPLIED duplicate returns the stored outcome. A changed payload under the
same event ID is rejected. A PENDING command, actor exception or uncertain
commit stops the current actor graph. Recovery constructs fresh actors, verifies
SQLite and the hash chains, replays journaled calls in order, compares outcome
and rolling state hashes, then runs read-only Unit 1 reconciliation. A pending
last command is re-executed only in the fresh graph. An APPLIED FRAME without
FRAME_DONE resumes its deterministic fan-out before accepting later inputs.
QUARANTINED commands and corrupt or incompatible journals fail closed.
An exception between journaled fan-out commands also marks the in-memory
runtime unusable. Its APPLIED prefix remains durable and FRAME_DONE is absent;
fresh recovery resumes that frame. A persistent callback failure makes
recovery fail closed rather than presenting an incomplete frame as healthy.
Terminal facts committed before a later failed RISK call remain APPLIED. Writer
epochs fence older processes. This is local deterministic replay, not
exactly-once external delivery.

`entry_fill()` requires an explicit approved full-quantity simulated fill and
an explicit tick-aligned take-profit target and slippage. `exit_fill()` and
`cancel()` forward explicit offline events. Pending M9.1 intents are expired
through its authoritative `expire()` transition at the first subsequent frame
at or after validity expiry; `expire()` also supports an explicit offline
clock event. There is no partial fill or venue
reconciliation. An M8 reservation left by a denied M9.1 admission remains
visible in Unit 1's `pending_reservations` and blocks later RISK work. Under
the accepted Unit 1/M8 contracts, only an authentic M7 terminal handoff can
release that no-order reservation; `cancel()` requires an admitted intent.
Until such a handoff is journaled, the session remains blocked. It is never
silently released or treated as fresh available capital.

## Verification boundary and limitations

`tests/test_paper_runtime.py` covers source-frame journaling, real M7-qualified
handoff through M8/M9.1, denied decisions, duplicate inputs, stale writer
fencing, corrupted commands, pending replay before/after actor mutation,
resumed frame fan-out, terminal durability before a later RISK failure, and
entry/funding/automatic target-exit replay against M8 accounting. Its
qualified-signal seam uses an explicitly synthetic fixture carrying a real M7
qualified record at its original availability time; the production
`CandleDecisionDriver` is exercised in the ordinary candle test and retains its
9,600-bar warmup rule.

Verification on 2026-11-15 with `PYTHONDONTWRITEBYTECODE=1 python -B`:
Unit 4 22/22, Unit 1 12/12, Unit 2 11/11, Unit 3 17/17,
M8 portfolio 13/13, M8 risk 33/33, M9.1 bridge 28/28; all focused commands
exited 0. `python -B -m unittest discover -s tests` ran 481 tests in
113.669 seconds: 481 passed, 0 failures, 0 errors, 0 skipped, exit code 0.
The prior independently verified 459-test baseline plus 22 new Unit 4 tests
accounts for the count change. This is Codex verification; independent Unit 4
review remains outstanding.

This unit supplies a callable offline session runtime, not an exchange feed or
paper venue. The caller still must provide validated chronological candles,
quotes, instrument specifications, fee and cost models, historical funding
eligibility, explicit entry fills and take-profit targets. No historical
profitability, external state reconciliation, or paper-trading readiness is
established. SQLite verification and Unit 1 reconciliation scan the full
history at recovery/checkpoints; performance on a full multi-year session has
not been benchmarked.
