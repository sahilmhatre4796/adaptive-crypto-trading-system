## Stage 1 — Context assembly

Implemented `trading/signal_context.py`: frozen `SignalContextConfig`, `ContextSource`, `SignalContext` and `assemble_context(pattern, candle, structure, structure_candle, m6, *, as_of, mode, config)`.

Roles are fixed to supported BTC/USDT or ETH/USDT, a 15m M3-v2 pattern, 5m independent confirmation, primary 15m M5 structure, 15m ATR/optional relative volume, 1h directional context and 4h regime. The builder checks M3-v2 configuration identity; M5/M6 must share the exact asset/decision cutoff. Existing M6 nested validation is reused without replacing its original input objects. Current-only records or CURRENT results cannot be passed as historical context.

No freshness limit, numeric weight or score threshold is invented. `SignalContextConfig` requires explicit `structure_max_age_seconds`, `range_direction` (NEUTRAL or UNKNOWN), and `transition_regime` (UNCERTAIN or UNKNOWN). These mappings never turn uncertain/neutral evidence into a directional vote. Directional BULLISH/BEARISH states retain their identities; 1h TRANSITION is UNKNOWN. Tests use explicit synthetic policy settings, not calibrated strategy defaults.

M5 exposes last receipt rather than last candle close. A matching 15m source `ClosedCandle` must therefore be supplied separately; freshness uses its price close and its availability must match the structure result. Omission yields missing context rather than assumed freshness. Matching timestamps cannot authenticate that the caller supplied the actual original source candle; this remains an upstream provenance boundary. All original M5/M6 records, input/configuration identities and source objects are retained.

The 1h/4h sources have independent status, source close, availability and freshness checks. Each must satisfy both its M6 freshness configuration and its respective role interval. Delayed receipt cannot refresh an old close. Missing, insufficient, unavailable and stale evidence remains UNKNOWN/non-directional with explicit reason codes. A context assembled now preserves actual source availability rather than stamping every field with assembly time. Full original M6 observation/publication/receipt records remain in the returned context.

Location is obtained only from fresh M5 `level_distances()` using the completed confirmation close and fresh 15m ATR in quote units. Missing ATR cannot become zero or a fabricated level. Optional relative volume is retained only in ratio units. `structure_eligible` requires a relevant level within the original pattern's M3 context-distance limit; it does not authorize a signal. Existing zone-state/reversal and M3-v2 context scoring rules remain unchanged.

The builder exposes overlapping/stale confirmation and expired-pattern reasons, leaving M3's existing terminal/stop-first lifecycle authoritative. It does not mutate pattern events or generate candidates, decisions or orders. M3 still requires adequate known context for CONFIRMED: missing macro evidence produces WAITING, never a bullish/bearish vote or a fabricated confirmation. M7 adds no automatic volatility blocker; M3's existing pattern-range/ATR filter remains in force.

Provider/news/risk/order integrations, paid APIs and new dependencies are outside scope. No profitability or paper-trading readiness is claimed.

## Stage 2 — Qualification and descriptive scoring

Implemented pure `evaluate_signal(context, config)` in `trading/signals.py`. `SignalConfig` requires a policy version, all four group caps, an explicit BLOCK/RECORD_ONLY rule for every defined contradiction, an explicit derivative interpretation map (possibly empty), a boolean directional-structure requirement and an optional explicitly supplied TTL. There are no production weight, threshold, freshness or TTL defaults. Policy tuples are canonicalized for deterministic identity.

Groups are pattern, structure, macro and derivatives. Pattern support is the existing geometry rank /100, not M3's context-inclusive strength. Structure uses its fresh BULLISH/BEARISH trend; RANGE is neutral, UNKNOWN supplies no direction. Known aligned 1h/4h evidence supplies at most one macro support unit; both opposite/aligned sources remain separately explainable. Derivatives contribute only through caller-supplied named-condition mappings and fresh observation IDs; unmapped data is contextual. Repeated feeds do not multiply group strength. Each group has maximum support/conflict units of 1, except pattern support uses its bounded geometry rank. Contribution is `cap * clamp(support - conflict, -1, 1)` when available, otherwise None. Missing weight is never redistributed. Score is bounded by +/- the sum of explicit caps and is descriptive only: no score threshold authorizes qualification.

Qualification requires actual M3 CONFIRMED, fresh meaningful M5 location, any explicitly enabled directional-structure requirement and no BLOCK contradiction. RECORD_ONLY never overrides M3's own context/expiry/invalidation rules. Missing macro remains non-directional and M3 WAITING; optional derivative absence does not block otherwise valid core evidence. Heatmaps and M6 volatility states remain explanatory. Existing M3 ATR filtering is preserved. `SignalEvaluation` separates qualification, score, group coverage and `confidence=None` / UNCALIBRATED, retaining its original context and provenance. Serialization is finite JSON-safe.

Stage 2 focused verification: **13 tests passed in 2.379 seconds**. All 82 baseline files remained byte-identical at that checkpoint. The pure evaluator must not be used as a replay/deduplication service; use the tracker below.

## Stage 3 — Immutable lifecycle

`SignalTracker(config, context_config, *, mode)` freezes a policy and explicit BACKTEST/CURRENT mode. `observe(context)` returns a frozen `SignalRecord`. WAITING observations may be followed by a new eligible candle; the first actual M3 CONFIRMED result makes exactly one qualification decision. A failed qualification consumes the formation as REJECTED. M3 INVALIDATED, EXPIRED and REJECTED are also terminal. Identical duplicate observations return the original record; later context cannot retry the same candle or reopen a consumed formation. Per-candidate chronology includes duplicate observations. Pattern rewrites, revised observed candles and changed inputs at the same decision timestamp are rejected.

Replay must include every eligible 5m candle beginning with the first candle whose opening is at or after the pattern's actual availability. A skipped eligible candle before expiry raises an error instead of assuming it did not confirm. A candle already open at delayed pattern receipt cannot independently confirm it. Terminal expiry may be recorded without reconstructing skipped decisions. Callers must submit observations at their actual historical availability, not rerun revised data as if originally known. Later genuine evidence may affect a subsequent WAITING candle but never changes existing history.

Candidate IDs hash schema namespace, policy identity, mode, symbol and original pattern ID. Decision IDs also hash decision time, candle opening and the complete input identity. Qualified signal IDs hash candidate ID, side and actual confirmation candle opening. Policy identities include both immutable signal and context settings. Equal inputs and replay order produce equal records and IDs. Independent policies/modes deliberately have different identities; cross-policy deduplication is outside M7.

Signal expiry is `min(pattern.expires_at, decision_time + configured_TTL)` when TTL is supplied, otherwise the original pattern expiry. `observe_signal(signal_id, candle, *, as_of)` allows price-only monitoring even if M5/M6 later becomes unavailable. A new independent 5m candle touching the original pattern extreme appends a linked INVALIDATED event. Expiry appends EXPIRED at its actual observation time. Expiry takes priority at/after validity end. Neither event rewrites the qualified decision; duplicate terminal checks return the original linked event. Post-signal replay gaps also raise errors before expiry. Observation freshness for confirmation/monitoring follows M3's receipt-based 5m contract; M5/M6 context additionally uses original price/observation age. A delayed candle is never backdated. Monitoring is analytical evidence, not a risk-control service.

If qualification occurs mid-candle, monitoring begins at the next 5m opening at or after signal availability. For example, a signal qualified at 01:21 excludes the already-open 01:20–01:25 candle, even if its completed OHLC crosses the invalidation level. OHLC cannot establish whether that touch occurred before or after qualification. The first independent monitored candle is 01:25–01:30; M7 neither infers intrabar ordering nor retroactively invalidates from the excluded candle. This leaves that partial-candle interval unmonitored under the existing analytical contract.

For a previously unevaluated independent candle before signal expiry, observing at or beyond its receipt plus 5 minutes raises `ValueError` identifying stale invalidation evidence. It does not store the candle fingerprint, advance tracker chronology or append events. Callers must halt and reconstruct a causal replay from original observation history rather than silently continue with missing invalidation evidence. Already-processed duplicates remain idempotent; expiry and existing terminal events retain their precedence. This exclusive 5m receipt deadline differs from the inclusive context deadlines: M5 source age equal to configured freshness, and M6 role age equal to the smaller of its configured age and role interval, remain AVAILABLE; one second beyond is STALE.

## Exact M7-v1 contracts and M8 boundary

Inputs remain the existing immutable M3 `PatternEvent` and 5m `ClosedCandle`, M5 `StructureResult` plus its latest 15m `ClosedCandle`, and validated M6 `M6Bundle`. M3 geometry/context configurations and M5/M6 configuration identities are carried through, not replaced. The API does not resample candles or infer a missing receipt. Upstream code owns candle construction, source normalization and genuine provenance; M7 owns role/cutoff eligibility and evidence combination. A caller must use `assemble_context` rather than construct or replace a `SignalContext` manually. Dataclass constructors are trusted in-process contracts, not a validator for untrusted wire input. M6's reviewed deserializer validates its nested wire boundary; M7 does not add a wire deserializer or durable restart loader.

`SignalEvaluation.to_dict()` and `SignalRecord.to_dict()` use the existing finite JSON-safe normalizer: timestamps become ISO strings, tuples become arrays, and nested dataclasses retain their fields. Schema is `M7-v1`. Side is LONG/SHORT/None, decision LONG/SHORT/NO_TRADE, lifecycle WAITING/QUALIFIED/REJECTED/INVALIDATED/EXPIRED. `reference_price` is the completed confirmation close, not a fill quote. Confidence remains explicitly uncalibrated; coverage is a list of evidence groups, not a probability or a substitute confidence percentage.

M8 must preserve schema/policy/source identities and actual availability timestamps, consume only qualified and unexpired records, and apply linked terminal events. M8 must independently handle risk, sizing, fill assumptions, portfolio limits and execution permissions; none is authorized by an M7 record. M7 has no M8 integration code. Restart recovery, persistent history and input authentication are not implemented. The in-memory tracker must be deterministically replayed from the beginning with original observation history.

## Policy choices and limitations

No trading policy has been silently selected: callers must choose caps, all contradiction actions, structure freshness, RANGE/TRANSITION mappings, whether directional structure is required, derivative mappings and TTL explicitly. Test caps and settings are synthetic and have no performance claim. No performance optimization, provider calls, news dependencies, orders, position sizing or backtest execution integration is included. Existing M3 still requires usable macro evidence for confirmation, which is stricter than an optional M7 directional vote. M7 cannot relax that gate without changing the protected upstream contract.

Heatmaps, including historical-eligibility metadata, remain in the original M6 bundle for explanation only. CURRENT-only external snapshots are rejected in BACKTEST mode by existing M6 validation and M7 mode checks. Missing/unavailable heatmaps or derivatives produce no negative directional vote and cannot create a candidate. Known neutral evidence has zero M7 directional contribution even though preserved M3-v2 may treat it as compatible context.
