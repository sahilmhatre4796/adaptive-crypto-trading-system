# M6 — Market regime, derivatives and estimated liquidation zones

Implemented as a deterministic, offline analysis layer. M6 produces evidence for future M7; it does not change the baseline backtester, generate entry plans, approve risk, or place orders. M4 remains on hold and is not imported. No account, API subscription, key, deployment, package installation or provider connection was made.

Implementation baseline: clean `master` at `abcfbc92d9848f9d4e7a4ebea0ab786771144f23`, preserving M0–M3 checkpoint `9442bc4`, M5 `cc607f2`, and the separate M3 review fixes. The pre-edit byte hashes of all 62 tracked files were recorded in the ignored local verification file `runs/m6-preservation.json`. Existing files are not modified by M6.

Supported normalized symbols: **BTC/USDT, ETH/USDT**. Regime OHLC accepts **5m, 15m, 1h, 4h, 1d** with UTC open timestamps. Derivatives additionally allow `snapshot`. Heatmap core accepts the five intervals plus `snapshot`, but a `HeatmapSnapshot` must explicitly declare source-supported intervals and belong to one of them. Configuration permits disabling any interval. There is no implicit resampling or cross-timeframe averaging. Tests at several intervals demonstrate core support, not provider availability.

The CoinGlass decoder exposes **snapshot only**. It does not claim that matrix columns constitute independently captured historical observations or enable every core interval for that provider. Binance decoders likewise retain snapshot/sample identity rather than relabeling a response as a historical candle bucket. Funding period metadata is separate from analysis timeframe.

## Shared data and reliability contract

`Source(provider, venue, instrument, methodology)` identifies one data/method stream. An instrument denotes a specific contract, not all venues for a coin. Units belong to each metric or snapshot. Distinct providers, venues, methods, units or periods are never silently pooled into one comparable series.

`ObservationTime(observed_at, received_at, published_at=None, historical_eligible=False)` distinguishes market/model observation, optional publisher release and actual local receipt. Require observation <= publication <= receipt; omitted publication stays unknown, with observation as its validation lower bound. `available_at` is receipt, never observation. Timestamps are UTC; numeric project timestamps are epoch milliseconds. Provider decoders handle their documented seconds/milliseconds explicitly. Missing, invalid or reversed timestamps fail validation.

`historical_eligible` is an explicit provenance assertion by the data owner: immutable data genuinely captured/available at its recorded receipt. It is **false by default and always false in the supplied vendor decoders**. It cannot establish truthful provenance by itself. A future lawful archive adapter must verify actual archived receipt/revision records before setting it; changing the flag on today's response is not a historical data source. No archive or recorder was implemented.

External engines default to `mode='BACKTEST'` and reject current-only records. `CURRENT` must be chosen explicitly. Every selection also requires receipt <= decision cutoff. Freshness is measured from observation, so delayed receipt does not refresh old data. Revisions with a later receipt cannot affect an earlier decision. Exact repeated IDs collapse; conflicting values under the same identity raise ValueError. These are stateless replay/deduplication guarantees, not a durable ingestion database or restart protocol.

Output statuses distinguish AVAILABLE, PARTIAL, UNAVAILABLE, STALE and INSUFFICIENT. Missing metrics, intensity or quality remain `None`/UNKNOWN; observed numeric zero is retained when valid. Malformed inputs fail with errors rather than become neutral evidence. Stale values may be retained as raw audit records, but supply no current interpretation/clusters. Historical interaction events can remain in a stale result and must not be counted as fresh signals.

Candles reuse the existing OHLC validator and UTC conventions, with a separate M6 daily-capable boundary/continuity check. Duplicate/gapped/off-boundary bars, invalid OHLC, negative/nonfinite supplied volume, false/missing supplied close flags and nonmonotonic receipt are rejected. Future/unavailable candles are excluded before indicator calculations. Optional volume column omission gives `None`; an explicitly supplied invalid volume is an input error. Missing candle receipt retains the inherited **assumed-at-close research convention**, recorded in regime reasons; it is not verified exchange latency. Caller-supplied candle revisions must be selected as of receipt upstream; duplicate candle versions are rejected.

## Market regime methodology and configuration

No model fitting, optimization or full-sample percentile thresholds occur. Fixed research thresholds are configured before evaluation; calibration must use training data separately in later evaluation.

Defaults:

| Setting | Default / calculation |
| --- | --- |
| EMA structure | 20 / 50; close above fast above slow for bullish, reverse for bearish. |
| Slope | Slow EMA change over 3 bars divided by current ATR; directional magnitude at least 0.10 ATR. |
| ADX / ATR | Existing project implementations, 14 bars. ATR is the existing rolling true-range mean; ADX uses the inherited exponential smoothing. No alternative formulas replace them. |
| Direction | ADX >=25 plus aligned EMA structure and slope gives BULLISH/BEARISH. ADX <=18 plus absolute slope <0.10 gives RANGE. Otherwise TRANSITION. A fully flat price window is explicitly RANGE even though inherited ADX is undefined; undefined ADX is not imputed as zero. |
| Persistence | Same candidate state for 2 completed observations; disagreements give TRANSITION at the current availability, without backdating the change. |
| Bollinger width | 4 × population rolling close standard deviation / rolling mean ×100, over 20 bars; equivalent to total width of symmetric 2-standard-deviation bands. |
| Volatility state | HIGH requires ATR% >=3.5 **and** width% >=10; LOW requires ATR% <=0.3 **and** width% <=1; otherwise NORMAL. |
| Expansion/contraction | Current ATR% and width divided by their separately shifted, prior-20-bar medians. Both >=1.3 gives EXPANSION; both <=0.75 gives CONTRACTION; otherwise STABLE. A zero baseline gives UNKNOWN, not an infinite ratio. |
| Volume | Optional current volume / preceding 20-bar mean. No zero baseline substitution. It is descriptive evidence, not a directional vote. |
| Freshness | Latest candle price close at most one timeframe interval old. Delayed availability must also be <= cutoff. |

Warmup covers all EMA/ADX/slope/width/reference and persistence windows; short history gives INSUFFICIENT with UNKNOWN states. Each reused indicator is computed once per analysis. `confidence` is **binary rule agreement**: 100 when all persisted classification rules agree on BULLISH/BEARISH/RANGE, 0 for TRANSITION/unknown. This is not a calibrated probability, reliability estimate or profitability score. All measured indicator values and input candle IDs are separate evidence. `available_at` identifies when the classification became knowable; `candle_closed_at` identifies the source close.

## Derivatives methodology and configuration

Normalized metrics: funding rate, open interest, price, volume, long/short ratio, basis, observed long liquidation totals and observed short liquidation totals. Observations carry units and, where relevant, a period in seconds. Acceptable units are explicit (`fraction`, `ratio`, `base`, `contracts`, `USD`, `USDT` by metric); units are not converted or assumed interchangeable.

`MetricPolicy(metric, max_age_seconds, threshold, period_seconds=None, enabled=True)` configures each independently. Default funding is stale after 28,800 seconds and unusual at +/-0.0005 **fraction per verified 8-hour period**. A different/unknown funding period is unavailable for that threshold until the policy is changed explicitly. The Binance decoder requires caller-verified period metadata instead of guessing eight hours. These observations never debit the funding ledger.

Other defaults: freshness 900 seconds, OI movement 3%, price movement 0.1%, volume movement 20%, ratio crowding >=1.5 or <=1/1.5, basis premium/discount +/-0.5%, liquidation-activity movement 100%. Changes are `(current-previous)/previous`, with a positive baseline and maximum observation gap 3,600 seconds. No baseline/zero baseline yields no change. Funding/basis labels compare observed levels; OI/volume/liquidation movement labels compare successive values.

Four price/OI combinations are emitted as descriptive evidence. Price/volume divergence includes rising or falling price with falling volume. Paired interpretations require the same provider/venue/instrument and **exactly matching current and preceding observation times**. No automatic interpolation, asynchronous pairing or market-wide positioning inference occurs. Long/short labels explicitly say POTENTIALLY crowded and retain a provider-sample limitation. They do not prove actual positions across the market. OI threshold crossings also produce sudden-activity evidence.

Each result preserves current and prior observations, change, age, status, condition and reasons. Result confidence is **fresh metric coverage** across enabled metric policies, 0–100; multiple feeds for one metric cannot inflate coverage. It is not a directional prediction. Streams with different units/periods remain separate, ordered deterministically.

## Liquidation heatmap methodology

`LiquidationCluster` stores an identity, positive lower/upper bounds, LONG or SHORT estimated position side, optional nonnegative intensity, optional provider quality in [0,1], and side-estimation method. At a snapshot's reference price, long zones must lie strictly below and short zones strictly above; ambiguous overlapping sides are rejected rather than invented. A source may provide a single level (`lower == upper`). Missing intensity/quality stays unknown.

`HeatmapSnapshot` adds source/method, units, reference price, timeframe capabilities, observation/publication/receipt times and immutable clusters. Core analysis never derives price levels or intensities from OI, leverage assumptions, M5 pivots or future candles. The CoinGlass decoder classifies side **relative to its reported reference price**, explicitly tagged PRICE_RELATIVE_ESTIMATE; this is not provider-disclosed position direction. Its last-column point levels get no fabricated bin widths, confidence or old-cell forward fills.

Distances use the nearest edge: `100 * max(lower-price, price-upper, 0) / price`; inside a zone gives zero. The original estimate's side is retained if price later crosses it, with current location ABOVE/BELOW/INSIDE reported separately. Proximity ranks by distance then cluster ID. Intensity ranks by descending raw score then ID. Relative intensity is score / maximum nonzero score **within this one snapshot/method/unit stream**. Default major threshold is 0.75 of that maximum; nearby means within 1%. All-zero or missing intensity cannot produce relative intensity/significance. Missing some intensities makes the result PARTIAL.

Long/short concentration shares divide the sum of known dimensionless relative scores on each side by the total relative-score sum, only when all supplied cluster intensities are known and the total is positive. They describe the supplied model bins, not money, expected liquidations, market coverage or independent positions. Overlapping estimates are not deduplicated into actual exposures. Never combine these shares/raw scores across providers, model versions or intervals. Provider quality, if present for every reported cluster, gives conservative minimum quality ×100 as heatmap confidence; otherwise confidence is None. Intensity is never substituted for quality.

Interaction rules use completed price bars and only snapshots available **at or before bar OPEN**, still fresh at bar receipt:

- APPROACHING: closing distance is positive, within the configured near threshold and less than opening distance.
- ENTERING: observed candle range intersects the zone, including an open inside it.
- THROUGH: candle opens on the original price side and closes beyond the opposite zone edge. A gap already beyond a zone is not evidence of traversal.
- SWEEP_REVERSAL: price starts outside on the original side, strictly passes the far edge and closes back beyond the near edge; extreme-to-close reversal must reach 0.1% by default. Side-mirrored for long/short zones.
- THROUGH_NO_REVERSAL: a **later separate bar** remains completely beyond the zone after a THROUGH event. It means no zone revisit was observed in that bar; it makes no claim about subsequent prices.
- STRENGTHENING/WEAKENING: successive available snapshots of the same source/method/unit/timeframe, with the same cluster ID/bounds/side, change intensity by at least 25% against a positive baseline. Both observations must still be fresh at current receipt. Missing/disappearing bins, moved ranges, zero baselines and stale/delayed observations do not become zero-filled changes. Events use current receipt, never earlier observation time. Late revisions to older observations cannot remove prior events.

Per-snapshot/cluster/kind price events emit once in each replay; IDs also record the triggering bar. Model-change events reference both snapshots. Event output is deterministic, chronologically sorted and preserves receipt, price close and source IDs. A price touch is **never labeled LIQUIDATED**. Same-bar OHLC cannot identify tick paths; the rules conservatively require explicit open/extreme/close relationships. Max snapshot age defaults to 900 seconds, max price age to one price interval. Configure separately for a slower source; late data never refreshes itself.

## Historical capabilities and lookahead prevention

No genuine historical heatmap archive was acquired. Historical heatmap strategy validation is **unavailable**. A heatmap response generated now cannot enter a past simulation, even if its matrix depicts past price periods. This implementation uses only the decoder's final column as one current observation, timestamps generation/receipt honestly and sets historical eligibility false. Price interactions with a current response are never reconstructed for its earlier matrix columns. No current estimate is forward-filled backward into old decisions.

The core supports verified archived snapshots if supplied with immutable original receipt/revision metadata and legitimate access. Tests use explicitly synthetic, point-in-time fixtures to verify that capability; they are not market validation. Every simulated decision must use its own `as_of` and BACKTEST mode. Slice all components at that same cutoff. External records arriving later remain excluded, including revisions; availability cannot precede receipt. M6 does not inject external evidence into the original ledger/strategy or produce historical performance statistics.

## Stable M7 contract and usage

```python
from trading.regime import RegimeEngine
from trading.derivatives import DerivativesEngine
from trading.liquidation import HeatmapEngine
from trading.m6 import M6Bundle

# All inputs are supplied data; no network request occurs in these calls.
regime4h = RegimeEngine().analyze(ohlcv4h, 'BTC/USDT', '4h', as_of=decision_at)
derivatives = DerivativesEngine().analyze(
    normalized_metrics, 'BTC/USDT', '5m', as_of=decision_at, mode='BACKTEST'
)
heatmap = HeatmapEngine().analyze(
    verified_archived_snapshots, ohlcv5m, 'BTC/USDT', '15m',
    price_timeframe='5m', as_of=decision_at, mode='BACKTEST'
)
bundle = M6Bundle('BTC/USDT', decision_at, (regime4h,), (derivatives,), (heatmap,))
payload = bundle.to_dict()  # json.dumps(payload, allow_nan=False) is supported.
```

The bundle carries separate timeframe results rather than manufacturing a combined score. Regime includes classification, volatility state/change, indicator evidence, candle IDs, source, cutoff and availability. Derivatives include raw/current/prior observations, funding conditions, changes, interpretations, freshness and provenance. Heatmaps include long/short estimated zones, distances, ranks, relative intensity, quality, current location, model shares, interactions, current source snapshot and price-bar IDs/source. Configuration and algorithm identity accompany each component.

M7 must check status, mode, timeframes, freshness, source and confidence semantics before using evidence. Regime confidence is rule agreement, derivatives confidence is metric coverage, and heatmap confidence is optional provider quality: they must not be averaged as probabilities. A 5m classification cannot be promoted to 4h regime/1h direction. A TRANSITION/unknown/stale classification must not become favorable M3 context. M5 level distances and M6 regime/derivatives/heatmap evidence remain distinct; correlated price-action sweeps, OI activity and model bins must not be counted repeatedly. No automatic M3 context injection or M7 confluence engine was added.
